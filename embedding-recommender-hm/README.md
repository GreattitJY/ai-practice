# 임베딩 기반 상품 추천 (H&M)

"현대 AI의 원리와 구조" 3-2강(임베딩과 벡터의 원리) 실습.
H&M의 실제 상품·구매 데이터로, 고객이 산 상품들의 평균 벡터와 가까운 상품을 추천하고
다음 주에 실제로 산 상품을 맞히는지 평가한다.

작은 데이터로 한 같은 실습: `../embedding-recommender-dummyjson`

## 실행

| 단계 | 명령 | 결과 |
|---|---|---|
| 1. 제품 테이블 | `.venv/bin/python scripts/01_build_table.py` | 상품 47,224개(색상 버전을 상품 단위로 묶음), 구매 3,179만 건 |
| 2. 자연어 평탄화 | `.venv/bin/python scripts/02_flatten.py` | `data/products_flat.jsonl` |
| 3. 벡터 변환 | `caffeinate -i .venv/bin/python scripts/03_embed.py --limit 10000` | 판매량 상위부터. 멈춰도 다시 실행하면 이어서 함 |
| 4~5. 추천 | `.venv/bin/python scripts/04_recommend.py` | 무작위 고객 3명의 추천. `--customer`, `--product`, `--dim` |
| 평가 | `.venv/bin/python scripts/05_evaluate.py` | 마지막 7일 실제 구매 기준 HitRate·Recall·Precision, 인기순과 비교 |

3단계는 LM Studio 로컬 서버가 필요하다: `lms server start`, `lms load text-embedding-qwen3-embedding-4b`.
M1 Pro 기준 초당 약 3.8건(1만 개 약 45분, 전체 약 3.5시간).

## 설계 메모

- **상품 단위**: 색상 버전(105,542개)마다 설명이 같아서, 상품(product_code) 단위로 묶어 임베딩한다.
- **평탄화**: 이름·종류·대상 코너·소재 분류·무늬·설명을 문장으로 만든다. 색상은 상품의 성격이 아니라 고를 수 있는 옵션이라 뺀다.
- **지시문 없음**: 상품과 상품을 비교하는 대칭 구조라 `Instruct:` 접두어를 붙이지 않는다(3-2강 p5).
- **정규화**: 상품 벡터와 평균 벡터를 모두 L2 정규화한다(3-2강 p8, p15).
- **평가**: 이미 산 상품은 추천에서 빼므로, 정답도 "처음 산 상품"만 센다.
- **상품 벡터에는 고객 데이터가 없다**: 임베딩 모델은 미리 학습된 Qwen3-Embedding-4B를 그대로 쓰고(추가 학습 없음), 상품 벡터는 평탄화 문장만으로 만든다. 구매 기록은 벡터가 만들어진 뒤 추천·평가 단계에서만 쓴다.

  | 단계 | 상품 정보 | 구매 기록 |
  |---|---|---|
  | 상품 벡터 만들기 (`03_embed.py`) | ✓ | ✗ |
  | 추천 (`04_recommend.py`) | ✓ | ✓ 산 상품의 벡터를 평균 내는 데만 사용 |
  | 평가 (`05_evaluate.py`) | ✓ | ✓ 정답(다음 주 구매) 확인에 사용 |

  그래서 벡터는 "설명이 비슷한 상품"끼리만 가깝고, "같이 사는 상품"이나 "요즘 팔리는 상품"은 모른다.
  구매 기록을 벡터에 반영하는 다음 단계 후보: 같이 산 상품 쌍으로 임베딩 모델 재훈련(3-2강 p11), 구매 기록만으로 상품 벡터 만들기(item2vec).

## 실험 결과 (판매량 상위 1만 개 임베딩)

평가 조건: 학습 기간 ~2020-09-15, 정답 기간 2020-09-16 ~ 09-22, 무작위 고객 2,000명(`--seed 42`), 추천 12개.
정답은 정답 기간에 "처음 산" 상품이다. 수치는 모두 HitRate@12(정답을 하나라도 맞힌 고객 비율).

### 기본 평가 (`05_evaluate.py`)

| 방식 | HitRate@12 | Recall@12 |
|---|---|---|
| 인기순 (직전 7일) | **0.141** | **0.073** |
| 임베딩 2560차원 | 0.013 | 0.006 |
| 임베딩 256차원 | 0.016 | 0.007 |
| 임베딩 64차원 | 0.006 | 0.002 |
| 무작위 (계산값) | 0.003 | — |

맞힌 고객이 수십 명 수준이라, 2560차원과 256차원의 차이는 의미 있는 차이로 보기 어렵다.

### 추가 실험 (스크립트에는 넣지 않은 일회성 실험)

**평균에 쓰는 최근 구매 수** (`--history`): 20개 0.013 → 5개 0.016 → 1개 0.021.
오래된 구매까지 섞을수록 평균 벡터가 흐려진다.

**카테고리별 평균 벡터 × 후보 제한**
카테고리별 평균: 최근 구매를 `product_group`으로 묶어 묶음마다 평균 벡터를 만들고, 추천 12개를 묶음의 구매 수에 비례해 나눠 뽑는다.
고객 한 명이 평균 4.5개 카테고리를 산다.

| 후보로 쓴 상품 | 후보 수 | 평균 1개 | 카테고리별 평균 |
|---|---|---|---|
| 전체 1만 개 | 10,000 | 0.013 | 0.015 |
| 최근 28일 안에 팔린 상품 | 6,134 | 0.016 | 0.019 |
| 최근 14일 안에 팔린 상품 | 5,276 | 0.017 | 0.021 |
| 최근 7일 안에 팔린 상품 | 4,604 | 0.018 | 0.023 |
| 최근 7일 판매 상위 1,000개 | 1,000 | 0.053 | 0.059 |
| 최근 7일 판매 상위 300개 | 300 | 0.080 | 0.091 |
| 참고: 인기순 (직전 7일) | — | 0.141 | |

### 해석

1. **카테고리별 평균은 여섯 조건 모두에서 조금씩 나았다.** 여러 취향을 평균 하나로 뭉개는 문제는 실제로 있다. 다만 효과는 작다.
2. **점수를 좌우한 것은 "얼마나 많이 팔리는가"였다.** 최근에 한 번이라도 팔린 상품으로 거르는 것만으로는 조금 오르고, 판매량 상위로 후보를 좁힐수록 크게 오른다.
3. **같은 후보(최근 7일 상위 300개) 안에서도 임베딩 순서(0.091)가 인기순 순서(0.141)보다 못했다.** 이 데이터에서는 "산 옷과 비슷한 옷"보다 "지금 많이 팔리는 옷"이 다음 주 구매를 더 잘 맞힌다.
4. **임베딩은 옷의 종류와 설명만 알고, 언제·얼마나 팔리는지는 모른다.** 상품 벡터를 만들 때 구매 기록을 쓰지 않았기 때문이다(설계 메모 참고). 패션처럼 유행과 계절이 빨리 바뀌는 분야에서 "다음 주 구매 맞히기"에는 불리하다. 반면 "이 상품과 비슷한 상품"은 잘 찾는다(`04_recommend.py --product 0`: 스키니진 → 같은 라인의 스키니진, 유사도 0.96~0.88).
5. 실제 추천 시스템은 임베딩 하나가 아니라 판매량·최근성·구매 기록 기반 모델 같은 여러 신호를 섞는다.
